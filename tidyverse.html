Welcome to the tidyverse

≈ 15 min

The tidyverse is a collection of R packages for reading, tidying, transforming and plotting data, all designed to work together. This course builds on R basics, so if you haven’t done that course yet, do it first.

What the tidyverse is

R comes with everything you need to work with data, but over the years its functions have grown up in different styles, with different names and orders of arguments for similar jobs. The tidyverse is a collection of packages that share a single design. Data are kept in tibbles, laid out in a consistent (“tidy”) way, and almost every function takes a tibble as its first argument and gives you a tibble back, so that the functions fit together. The core packages are:

PackageWhat it is for
tibbleTibbles, the tidyverse’s tables of data
readrReading data from text files into tibbles, and writing tibbles to files
tidyrTidying data, so that it is laid out in the right shape
dplyrChoosing, filtering, changing and summarising data
ggplot2Drawing plots and graphs

There are a few more, such as stringr for working with text, forcats for factors and lubridate for dates, which you won’t need in this course.

Installing and loading packages

A package is a bundle of functions (and sometimes data) that adds to what R can do. There are two steps to using one:

  • install.packages("tidyverse") downloads the package and installs it. You only need to do this once: on your own computer it stays installed, and here it is kept in your browser for the next time you come back.
  • library(tidyverse) loads the package into R’s memory, so that you can use its functions. You need to do this in every new R session: each time you start RStudio, restart R, or come back to this course.

When it loads, the tidyverse tells you which packages it has attached, and their versions. It also lists some conflicts, such as dplyr::filter() masks stats::filter(). This means that two packages have a function with the same name, and that, from now on, filter means the one from dplyr. That is what you want, so you can ignore the message. If you ever need the other one, you can name its package, as in stats::filter().

Reading data from files

≈ 25 min

Most data reach R in a file. readr, one of the packages of the tidyverse, reads files of data into tibbles, and it tells you how it has interpreted each column.

readr

readr has a function for each of the common kinds of text file of data, and functions that write tibbles back out to files:

FunctionWhat it does
read_csv("file.csv")reads a file of comma-separated values
read_tsv("file.txt")reads a file of tab-separated values (often ending in .txt or .tsv)
write_csv(data, "file.csv")writes a tibble to a file of comma-separated values
write_tsv(data, "file.txt")writes a tibble to a file of tab-separated values

Like any other function, read_csv() only gives you the data: it doesn’t keep them for you. To work with the data afterwards, store them in an object, as in child <- read_csv("Child_Variants.csv").

File paths and the working directory

A file path tells R where a file is. ~/data/small_file.txt is the file small_file.txt in the data folder of your home folder, which is what ~ stands for. You can give R the full path of a file every time, but it soon becomes tedious. Instead, you can set R’s working directory: the folder in which R looks for files, unless you tell it otherwise. Once it is set, the name of a file in that folder is enough.

  • getwd() tells you what the working directory is, and setwd("~/data") changes it to your data folder.
  • In RStudio, you can also choose Session ▸ Set Working Directory ▸ Choose Directory…, or go to the folder in the Files pane and choose More ▸ Set As Working Directory. RStudio shows you the setwd() command it runs, which you can copy into your script.

RStudio can also fill in file names for you. Type read_tsv(""), put the cursor between the quotes, and press Tab: RStudio lists the files in the working directory, and you can pick one rather than typing its name (and perhaps mistyping it).

Tidy data

≈ 10 min

A table of data can often be laid out in more than one way. The tidyverse has a clear opinion about which way is best, and its functions are designed around it.

Think of a simple experiment, in which two genes (ABC1 and DEF1) are measured in two genotypes (WT and KO), with three replicates of each. Here are the results in wide format, with a row for each gene:

GeneWT_1WT_2WT_3KO_1KO_2KO_3
ABC18.864.188.904.0014.5213.39
DEF129.6041.2236.1511.1816.681.64

This table is compact and easy to read, and you can see the measurements of each gene at a glance. But the genotype and the replicate of each value are hidden in the names of the columns, and the values are spread over six columns. If you wanted to record something else about each sample, such as the batch it was processed in, there would be nowhere obvious to put it.

Here are the same results in long format:

GeneGenotypeReplicateValue
ABC1WT18.86
ABC1WT24.18
ABC1WT38.90
ABC1KO14.00
ABC1KO214.52
ABC1KO313.39
DEF1WT129.60
DEF1WT241.22
DEF1WT336.15
DEF1KO111.18
DEF1KO216.68
DEF1KO31.64

This is more verbose, because values such as the gene names are repeated. But the genotype and the replicate are now columns of their own, all the measurements are in a single column, and recording the batch of each sample would simply mean adding a Batch column.

What makes data tidy

The long format is what the tidyverse calls tidy data:

  • each variable has its own column,
  • each observation has its own row, and
  • each value has its own cell.

The functions of the tidyverse expect data to be tidy. For a plot of the values coloured by genotype, for example, ggplot2 needs a column that says what the genotype of each value is, and the wide table doesn’t have one. Data often arrive in wide format, because that is how people lay out tables for reading, and the tidyr package has functions for converting between the two formats: pivot_longer() and pivot_wider().

Combining steps with pipes

≈ 25 min

Real questions usually take several steps: filter on one thing, then on another, then choose some columns. Pipes let you write those steps one after another, in the order in which they happen.

Suppose you want to find the people in trumpton who are at least 170 cm tall and called Chris, and see just their age and weight. That takes three steps. One way to do it is to store the result of each step in an object, and use that object in the next step:

> filter(trumpton, Height >= 170) -> answer1
> filter(answer1, FirstName == "Chris") -> answer2
> select(answer2, Age, Weight)
# A tibble: 1 × 2
    Age Weight
  <dbl>  <dbl>
1    26     90

This works, but it leaves objects you don’t need (answer1 and answer2) lying around in R’s memory, and it is hard to see what is going on.

The pipe: %>%

Every dplyr function takes a tibble as its first argument and gives you a tibble back. That means you can pass the result of one function straight into the next, without storing it. The pipe, %>%, does exactly that: it takes whatever is on its left and gives it to the function on its right as that function’s first argument. These two commands are the same:

R
select(trumpton, -LastName)
trumpton %>% select(-LastName)

So the three steps above become a single command, which you can read from top to bottom, saying “and then” for each %>%: take trumpton, and then keep the people who are at least 170 cm tall, and then keep those called Chris, and then select their age and weight.

> trumpton %>%
+   filter(Height >= 170) %>%
+   filter(FirstName == "Chris") %>%
+   select(Age, Weight)
# A tibble: 1 × 2
    Age Weight
  <dbl>  <dbl>
1    26     90

Writing each step on a line of its own makes a long command much easier to read. Put the %>% at the end of each line rather than the start of the next, so that R knows the command carries on. In RStudio, Ctrl+Shift+M (⌘+Shift+M on a Mac) types a pipe for you. Depending on RStudio’s settings (Tools ▸ Global Options ▸ Code), it may type |> instead: that is R’s own pipe, which works in the same way for everything in this course.

Several tests at once

You can also give filter() several tests, separated by commas, and it keeps the rows for which all of them are TRUE. These two commands are the same as the two filters above:

R
trumpton %>% filter(Height >= 170, FirstName == "Chris")
trumpton %>% filter(Height >= 170 & FirstName == "Chris")

& means “and”, | means “or”, and ! means “not”. %in% tests whether a value is one of a set of values, so filter(trumpton, FirstName %in% c("Chris", "Liam")) keeps the people called Chris or Liam, and filter(trumpton, !FirstName %in% c("Chris", "Liam")) keeps everyone else.

Your first plots with ggplot2

≈ 25 min

ggplot2 is the tidyverse’s package for plots. It is powerful and flexible, and it works in the same way as the rest of the tidyverse: the data come in a tibble, in tidy format, as the first argument.

How a ggplot is put together

Every plot in ggplot2 is built in the same way:

  1. Start with ggplot(), and give it the tibble that holds your data.
  2. Say which columns of the data should control which parts of the plot, with aes(). These are the aesthetics: the position along the x axis, the position along the y axis, the colour, the size, and so on.
  3. Add a geometry with +: the kind of plot you want, such as points, lines or bars.
  4. Add anything else you need, such as titles or labels, with more +.

The geometries all have names that start with geom_:

GeometryWhat it draws
geom_point()points: scatter plots and strip charts
geom_line()line graphs
geom_boxplot()box plots
geom_col() and geom_bar()bar plots
geom_histogram() and geom_density()distributions

R

Change geom_point() to geom_line(), and the same data are drawn as a line instead. Because the tibble is the first argument of ggplot(), you can also pipe the data into it.

Fixed and mapped aesthetics

An aesthetic can be set in two ways. A fixed value is the same for every point: all the points red, say, or all of them size 4. You give fixed values to the geometry, outside aes():

R
expression %>%
  ggplot(aes(x = WT, y = KO)) +
  geom_point(colour = "red2", size = 5)

A mapped aesthetic comes from a column of your data: points coloured by genotype, or sized by the number of observations. Mappings go inside aes(), as in aes(x = WT, y = KO, colour = genotype), and ggplot2 adds a legend to explain them. A mapping can be categorical (a column of text, which gives a separate colour for each value) or quantitative (a column of numbers, which gives a scale of colours from low to high).

The + goes at the end of the line

Like the pipe, the + that adds a layer must go at the end of a line, not at the start of the next one. If a line ends without one, R thinks the command has finished there: it draws the plot without the layer, and then complains about the + on the next line.

Bar plots and distributions

≈ 25 min

Points are only the start. ggplot2 has geometries for bar plots, histograms, density plots and many more, and they all work in the same way.

Bar plots: geom_col() and geom_bar()

There are two geometries for bar plots, and which one you need depends on your data. Use geom_col() when your data already contain the heights of the bars. Then you need two aesthetics: x for the bars, and y for their heights. To plot the expression of each gene in the WT samples:

R
expression %>%
  ggplot(aes(x = Gene, y = WT)) +
  geom_col(fill = "red2")

Use geom_bar() when you want ggplot2 to count things for you: how many rows there are for each value of x. It only needs the x aesthetic. For example, ggplot(small, aes(x = Category)) + geom_bar() draws a bar for each category, as tall as the number of samples in it.

Distributions: histograms and density plots

A histogram divides the range of the values into bins, and draws a bar for each bin, as tall as the number of values in it. The argument binwidth sets how wide the bins are. These examples use many_values.txt, which has 100,000 values from two genotypes:

R
many.values <- read_tsv("many_values.txt", show_col_types = FALSE)
many.values %>%
  ggplot(aes(x = values)) +
  geom_histogram(binwidth = 0.1, fill = "yellow", colour = "black")

A density plot (geom_density()) draws a smooth curve instead, which is often easier to read when you are comparing groups. Here the fill is mapped to the genotype, and alpha, the opacity, is set to 0.5, so that each curve shows through the other:

R
many.values %>%
  ggplot(aes(x = values, fill = genotype)) +
  geom_density(colour = "black", alpha = 0.5)
fill and colour

For a shape with an inside, such as a bar or the area under a density curve, fill sets the colour of the inside and colour sets the colour of its outline. For points and lines, colour is the colour of the point or line itself. The help page of each geometry (for example ?geom_histogram) lists all the aesthetics it understands.

Titles, labels and layers

≈ 15 min

A plot that someone else will read needs a title and clear labels. ggplot2 builds a plot up in layers, so you add these, and other annotations, with +.

ggtitle() adds a title to a plot, and xlab() and ylab() change the labels of its axes. A plot can also have more than one geometry, each of them a layer drawn on top of the ones before. geom_text() writes text at each point, taken from the label aesthetic. Here the names of the genes are written just below the points, because vjust = 1.2 moves each label down a little:

R
expression %>%
  ggplot(aes(x = WT, y = KO, label = Gene)) +
  geom_point() +
  ggtitle("Expression level comparison") +
  xlab("WT expression level (log2 RPM)") +
  ylab("KO expression level (log2 RPM)") +
  geom_text(vjust = 1.2)

The arguments hjust and vjust move the labels sideways and up or down. Try a few values to see what they do.

If you have time A line of best fit

This part is optional: it doesn’t count towards your certificate.

The plot shows that animals with heavier brains tend to have heavier bodies. You can test whether this relationship is significant, and measure how strong it is, with two functions that ask similar questions of the same data, but which are used in quite different ways. That is a good reminder to read the help page of a function before you use it.

cor.test() takes two vectors of the same length and tests the correlation between them. It gives you the correlation coefficient and a p-value. Use $ to take the log.brain and log.body columns out of brain, and note the p-value, so that you can add it to the title of your plot.

lm() fits a linear model. Its two main arguments are a formula, which describes the relationship you want to model, and the data. The formula log.body ~ log.brain means “log.body as predicted by log.brain”, so the command is lm(log.body ~ log.brain, data = brain). It gives you the intercept and the slope of the line of best fit, which you can draw on your plot with geom_abline(intercept = …, slope = …).

Test, and draw the line
  1. Test the correlation between log.brain and log.body with cor.test().
  2. Fit a linear model of log.body against log.brain with lm().
  3. Add the line of best fit to your plot with geom_abline(), and put the p-value in the title.
What p-value does cor.test() give for the correlation?
2.44e-06, which is 0.00000244: a highly significant correlation. The correlation coefficient is 0.77, and lm() gives an intercept of −2.283 and a slope of 1.215.
